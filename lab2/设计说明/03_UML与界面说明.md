## 1 图种与选型

共11张图，使用类图、组件图、部署图、用例图、状态图、时序图六种不同UML，覆盖结构、行为、交互三类；时序图和序列图不重复计数。

| 类别 | 图的名称 | 主要用途与本项目选择 |
|---|---|---|
| 结构性 | 类图 | 类的属性、方法和关联；本项目必画，拆为核心票务和业务记录两张 |
| 结构性 | 对象图 | 某时刻具体对象及链接的快照；可辅助解释某个订单，本次未选 |
| 结构性 | 组件图 | 模块职责和依赖；本次用于11个模块整体架构 |
| 结构性 | 复合结构图 | 一个分类器内部部件、端口和连接；当前无需另画 |
| 结构性 | 部署图 | 运行节点、执行环境和通信；本次表达本地单实例与离线端 |
| 结构性 | 包图 | 包的组织与依赖；当前以组件图及分层文字承接 |
| 结构性 | 剖面图 | 用构造型、标记值、约束扩展UML；本项目无特定领域UML扩展需求 |
| 行为性 | 活动图 | 流程、条件和并行分支；本次交互细节由时序图承接，未另选 |
| 行为性 | 用例图 | 参与者与系统能力、权限边界；本次分参与者和管理端两张 |
| 行为性 | 状态图 | 对象状态、守卫条件及允许转换；本次用于子票单 |
| 交互性 | 通信图 | 对象链接上的编号消息，强调协作网络；本次用时序图强调竞争顺序 |
| 交互性 | 交互概览图 | 多段交互的流程总览；本次用组件图和四段关键时序说明 |
| 交互性 | 时序图/序列图 | 通常为同一种Sequence Diagram的中文名称；本次绘制4张，不重复计数 |

## 3 UI工具与交互路径

以diagrams.net原生mxGraph画板格式保存可编辑控件和文字，文件为`UI界面/原型/票遇界面设计.drawio`（29页）。使用HTML/CSS/JavaScript补充可点击原型，通过本机Chrome导出PNG。画板是可编辑交换稿，字体及细节以HTML/PNG主预览为准；没有声称使用Figma或Pixso，也没有把图片导出当作后端实现。

打开`UI界面/原型/index.html`即可预览；移动页底部导航承接参与者操作，管理页左侧菜单便于审查所有界面。菜单刻意展示各角色设计页以便审阅，真实产品入口应按角色隐藏并由服务端校验。每页标注示例角色，资料和二维码均为测试展示。

参与者路径：注册/登录→活动列表→详情/选座→实名整单确认→模拟支付→电子票/订单→退票或转赠。候补独立进入队列，递补后转待支付或免费确认。组织者路径：工作台→编辑/场次配置→提交审核→名单与统计→取消延期申请。管理员路径：审核→权限→取消退款批次→核销纠错→审计。检票路径：在线核验→离线记录→恢复同步/异常复核。

布局采用紫色主操作、绿色有效状态、黄色待处理、红色风险文案，状态同时用文字说明，不只依赖颜色。票据转赠锁定、售罄、权限拒绝、退款失败及离线限制均明确给出后续入口。多观演人页面展示最多4人及混合票种控件；原型支付导航使用默认1张测试单，尚未构建完整购物车。
